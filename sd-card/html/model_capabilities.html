Recognition model capabilities

The neural-network (TFLite) models shipped with AI-on-the-edge, what each is for, and how to pick the right one for your meter. Based on the official Choosing the Model guide.

Two outputs, two jobs. Every digit/analog ROI is read by a model that returns either a discrete class (a whole number, e.g. exactly "7") or a continuous value (a fractional reading, e.g. "7.3"). Continuous models keep reading correctly while a digit or pointer is rolling between values - that's the whole point of them. Pick a digit model for the digit ROIs and an analog model for the analog ROIs; they're independent.

The four model families

Analog · continuous

ana-cont

Reads the angle of an analog pointer as a continuous 0.0-9.9. The recommended choice for all analog dial meters, especially water meters.
Continuous output · supports Extended Resolution · trained on the same data as ana-class100.
Digit · continuous

dig-cont

Reads a rolling / odometer digit as a continuous 0.0-9.9 using arc-tangent processing, so it stays correct through the transition between numbers (partial digits).
Continuous output · supports Extended Resolution · best for mechanical counters.
Digit · class-100

dig-class100

Classifies a digit into 100 steps (0.0-9.9) - effectively continuous, also handling the in-between (transition) states of rolling digits.
100-class output · supports Extended Resolution · alternative to dig-cont - try both.
Digit · class-11

dig-class11

Classifies a digit as one of 11 discrete states: 0-9 plus "N" (undecided/partial). Simple and robust for clean LCD / seven-segment displays; first-generation model and the safe fallback.
Discrete output · no Extended Resolution · shows "N" during transitions.

Which model for which meter?

Analog dial meters (water / gas pointers) → ana-cont (newest: ana-cont_1500_s2_q). Use an ana-cont model on every analog ROI.
Mechanical / odometer rolling digits (the digits physically roll) → dig-cont (newest: dig-cont_0900_s3_q) or dig-class100. Both read correctly while a digit is half-rolled - essential for accurate counts.
Clean LCD / seven-segment digits (no rolling, crisp segments) → dig-class11 (newest: dig-class11_1910_s2_q). Simplest and very robust; note it does not support Extended Resolution.
Partial / transition numbers (you need a reading mid-roll) → use a continuous digit model (dig-cont or dig-class100); avoid dig-class11, which reports "N" mid-roll.
Mixed meters (digits + an analog sub-dial) → combine: a digit model on the digit ROIs and ana-cont on the analog ROIs. Set "Analog to Digit Transition Start" in post-processing for hybrid readouts.

Reading the model name

Filenames follow [type]_[version]_[size][-q].tflite:

PartMeaning
typeana-cont (analog pointer, continuous), dig-cont (digit, continuous), dig-class100 (digit, 100 classes), dig-class11 (digit, 0-9+N).
versionFour digits: first two = main version, last two = sub-version. Higher is newer (e.g. 1910 > 1900).
size (s0-s3)Network size. Higher s-number = fewer parameters → smaller and faster, with newer training.
-qQuantized: significantly smaller and faster on the device, typically with no noticeable accuracy loss.
Not sure? The guide's advice: when two models could fit (e.g. dig-cont vs dig-class100, or ana-cont vs ana-class100), try both on your own meter and keep whichever reads more reliably. Start with the newest version of the recommended family for your meter type, and prefer the quantized (-q) build.
